Frequently Asked Questions

Answers about Nebulae devices, gateways, SDKs and middleware. Can’t find what you need? Our team is happy to help.

What is Nebulae?

Nebulae is a tangible framework for the Internet of Things. Nebulae provides networking hardware as well as SDKs and cloud services designed and engineered to simplify the implementation of IoT solutions.

What are the Nebulae devices?

Nebulae devices are divided into two categories:

  • NebuLink Node — a board-level component that provides IPv6 internet connectivity for sensors, devices and equipment. A NebuLink Node may be categorised either as a Full Function Device (FFD) or a Reduced Function Device (RFD), operating on battery supply or power line.
  • NebuLink Gateway — a device that builds and maintains an auto-configuring, self-tuning, redundant, self-healing network of NebuLink Nodes in a mesh, star, tree or hybrid topology, and securely connects them to Nebulae Cloud.
What are the system requirements to run Nebulae IoT products?

A host build system running Windows or Linux.

What connectivity protocols does Nebulae IoT support?

Zigbee, 6LoWPAN, Wi-Fi, Cellular, Ethernet, Bluetooth and more.

What is the RF range for each gateway?

Each NebuLink Gateway has Zigbee and 6LoWPAN with 100 metres range (line of sight).

How can I develop my application on the Nebulae platform?

You can build an IoT application using the Nebulae SDKs, with the help of the Doxygen documentation provided on the Nebulae platform.

Do you provide APIs for developing applications?

Yes. The APIs are documented in the Doxygen section of the respective SDK.

What kind of applications can be built on the Nebulae IoT platform?

Any IoT-based application can be built on the Nebulae IoT platform.

How are you different from other IoT providers?

We are scalable in terms of devices, and the Nebulae IoT platform is interoperable.

How many nodes or end devices can be connected to one gateway?
  • Zigbee devices — 15 to 20
  • 6LoWPAN devices — 70
Which operating systems does the gateway support?

FreeRTOS and Linux.

Which communication protocols do you support?

IEEE 802.11 b/g/n, IEEE 802.15.4, Ethernet, Cellular, Bluetooth Classic and BLE.

What is the bandwidth or range of each connectivity protocol?
  • IEEE 802.11 b/g/n — 802.11n (2.4 GHz), up to 150 Mbps
  • Ethernet — 10 or 100 Mbps
  • Bluetooth Classic or BLE — 10 to 100 metres range
How easily can the dashboard be customised to my requirements?

It is very easily customisable. Reach out to us at support@nebulae.io for details.

Do you provide SDKs along with the Nebulae products?

We provide SDKs after an NDA is signed, and with additional charges.

What is NebuLink Middleware?

NebuLink Middleware is a mediator between the hardware and the application. It integrates nodes and gateways with the application.

How much data can be stored in Nebulae Middleware?

Nebulae Middleware is scalable in terms of storage. It can be scaled by adding more servers to the Middleware cluster.

What other data storage options do you provide?

The NebuLink RTOS Gateway provides SPI flash memory (NLG1XXX) and an SD card (NLG2200) to store other data as your application requires.

  • Wi-Fi, Ethernet or Cellular

Yes, a FOTA (firmware over the air) service is provided.

NebuLink Gateway — RTOS SDK25

What is the NebuLink Gateway RTOS SDK?

An SDK for developing IoT applications that can be used in smart IoT products and services, home automation, medical devices and industrial IoT. It provides end-to-end connectivity over Ethernet, Wi-Fi or GSM to connect RF / WSN sensors to NebuLink Middleware.

What does the NebuLink Gateway RTOS SDK offer?

It supports ESP32 (Espressif Systems) and Nuvoton NUC472 (ARM Cortex-M4) targets, with FreeRTOS, a HAL, OSAL services and third-party libraries to create IoT applications. It provides network connectivity over Wi-Fi, Ethernet and cellular GSM, and Bluetooth for short-range communication.

How does the NebuLink Gateway RTOS SDK work?

Clone the SDK following the steps in the Doxygen documentation. It provides configurations to select targets as you need. It includes the toolchain, BSPs, OSAL services, protocols and examples, so you can build IoT applications quickly.

Can I use the RTOS SDK on my own boards or hardware?

Yes. Options are provided for development boards as well as custom boards. You configure and write the code for your own board or hardware.

How should I start with the RTOS SDK?

See the Doxygen documentation. Examples such as MQTT, ADC, RS485, CAN, flash, SD card, Wi-Fi, file system and HTTP server-client are included in the SDK for reference.

Is there a commercial licence for the RTOS SDK?

Yes. You sign a commercial agreement with a defined interval to use it as your requirements need.

Can I buy only Nebulae boards or hardware and use my own SDK?

Yes.

Do you provide application examples in the SDK?

Yes. See the Examples section of the Doxygen documentation, for example MQTT, ADC, RS485, CAN, flash, SD card, Wi-Fi, file system and HTTP server-client.

How can I update the image on the NebuLink Gateway?

You can update the image using UART or FOTA, as you need.

Does the gateway provide Modbus slave?

Yes. Modbus slave support has been added in software for both the NLG1XXX and NLG2200 gateways. At present, only the NLG2200 provides Modbus slave from the hardware side.

Does the gateway provide Modbus master?

Yes. Modbus master support has been added in software for both the NLG1XXX and NLG2200 gateways. At present, only the NLG2200 provides Modbus master from the hardware side.

Does the gateway SDK use open-source libraries?

Yes. A few open-source libraries are used. They are listed under “Licenses of Third Party Software” in the Doxygen section.

I cannot see any logs on USB. What should I check?

Check the following in order:

  1. The LED pattern, to see whether the board boots successfully.
  2. If the board started successfully, check that the SLS USB-2-UART connection is correct. More details are in the Doxygen documentation (Debug Accessories section).
How do I check serial logs on the console?

Use the SLS USB-2-UART connector to power the board and read the debug serial console logs at 115200 baud. More details are in the Doxygen documentation (Debug Accessories section).

How do I enable a component or library in the SDK?

Enable the component through the configuration using “make menuconfig”. See the Doxygen documentation for details.

I loaded the default example binaries but the gateway does not connect to Middleware. What should I do?

Check which connectivity-based example you loaded. Check the LED pattern to confirm the gateway is connected to the configured router or network. If the network LED pattern is correct, check that the cloud key is properly flashed or stored in the defined location, and check the cloud LED pattern. These checks help you find the problem.

Can I use a third-party cloud service with the NebuLink Gateway and RTOS SDK?

Yes.

Do you provide end-to-end development and technical support?

The SDK includes Doxygen documentation and examples for end-to-end development support.

How is the SDK different from the chip vendor’s BSP / SDK?

The chip vendor’s BSP supports only the HAL and drivers with examples. The NebuLink Gateway RTOS SDK adds OSAL services, network connectivity support and examples on top of that BSP, so you can create IoT applications with much less effort. It also supports multiple targets in a single SDK.

What development environment or OS is required?

Windows or Linux (Ubuntu). Details and steps are in the Doxygen documentation.

Do you support an IDE for SDK development?

We do not provide an IDE, but we suggest the Eclipse IDE for development and debugging.

How do I read the network connectivity state from the network LED (LED2)?

The network LED uses these pre-defined states:

  1. Solid glow — interface is starting and in progress.
  2. Low-frequency blink (500 ms on/off) — external network connectivity.
  3. Medium-frequency blink (250 ms on/off) — local network connectivity.
  4. High-frequency blink (100 ms on/off) — error in connectivity.
  5. Off — service has not started yet.
  6. Five medium-frequency blinks every 4 seconds — Wi-Fi access point mode, network creation. For STA and AP+STA, the configurations above apply.

See the Doxygen documentation for more details.

How do I read the cloud connectivity state from the cloud LED (LED3)?

The cloud LED uses these pre-defined states:

  1. Solid glow — cloud service is starting.
  2. Low-frequency blink — connection successful.
  3. High-frequency blink — service disconnected.
  4. Off — LED service has not started yet.

See the Doxygen documentation for more details.

How do I tell that the board has started successfully from the power LED (LED1)?

The power LED uses these pre-defined states:

  1. Night Rider pattern — firmware boot-up in progress (10-second timeout).
  2. High-frequency blink — issue during firmware boot-up.
  3. Solid glow — firmware booted successfully.
  4. Off — firmware did not start.

See the Doxygen documentation for more details.

How do I check whether the NLG1XXX board has entered boot mode?

Check the SLS USB-2-UART settings for the boot / run mode switch. With these you can put the board into boot mode to flash new firmware using a tool or script. See the Doxygen documentation for more details.

NebuLink Middleware18

What is NebuLink Middleware?

NebuLink Middleware is a mediator between the hardware and the application. It lets connected devices interact easily and securely with your applications and with other devices.

What are the best features of NebuLink Middleware?

Absolute control, continuous integration, quick response, and secure data transmission with encryption.

How does Nebulae Middleware work?

Connected devices such as sensors, actuators, embedded devices, smart appliances and wearables connect to Nebulae Middleware over WebSockets or secure MQTT. The Nebulae Middleware SDK allows secure, low-latency, low-overhead, bi-directional communication.

How does the Nebulae IoT gateway talk to the cloud, and which messaging protocol is used?

A hybrid encryption system based on RSA with a 2048-bit key pair and AES with a 256 (512)-bit key. The messaging protocols are MQTT and HTTPS.

Do you provide a FOTA service? How can the firmware be updated?

Yes, the NebuLink FOTA service is provided. To update the firmware, refer to our SDKs or contact us.

Which programming language is used for cloud applications?

Cloud applications can be developed in any language you prefer.

What security does NebuLink Middleware provide?

HTTPS, and RSA with a 2048-bit key pair and AES with a 256 (512)-bit key.

Which authentication protocols does NebuLink Middleware support?

OAuth 2.0 with HTTPS for application communication, and RSA with a 2048-bit key pair and AES with a 256 (512)-bit key for device communication.

Is my data secure with NebuLink Middleware?

Yes.

Can I use other cloud services if I do not want NebuLink Middleware?

Yes. We provide third-party cloud integration.

In which regions is Nebulae Middleware available?

Currently Nebulae Middleware is available in the Canada region. It can also be hosted on a private cloud, and we provide dedicated-server hosted Nebulae Middleware.

Which communication and authentication protocols does Nebulae Middleware support?

For control-plane operations, Nebulae Middleware supports HTTPS. For data-plane operations it supports HTTPS, WebSockets and secure MQTT, a protocol often used in IoT scenarios. You can use certificates generated by Nebulae Middleware, or certificates signed by your preferred Certificate Authority (CA).

What is the Device Gateway?

The Device Gateway is the backbone of communication between connected devices and the cloud. It supports the publish/subscribe (pub/sub) messaging pattern, which enables scalable, low-latency, low-overhead communication, and is useful where very large numbers of devices communicate frequently with minimal delay. Clients publish messages on logical channels called “topics”, and other clients subscribe to topics to receive them. The Device Gateway handles the communication between publishers and subscribers, so organisations no longer have to provision, operate, scale and maintain their own servers as device gateways.

What is MQTT?

MQTT is a lightweight pub/sub protocol designed to minimise network bandwidth and device resource requirements. It also supports secure communication using TLS and is often used in IoT. MQTT v3.1.1 is an OASIS standard, and the Device Gateway supports most of the MQTT specification.

What is the Nebulae Middleware Device SDK?

The Device SDKs simplify and speed up the development of code that runs on connected devices (microcontrollers, sensors, actuators, smart appliances, wearables and more). Devices can optimise memory, power and network bandwidth use, and communicate securely with low latency and low overhead over WebSockets and MQTT. The SDKs also speed up application development with higher-level abstractions, such as synchronising a device’s state with its Device Shadow in Nebulae Middleware.

Which device SDKs does Nebulae Middleware provide?

Currently the device SDK is provided in Java, Android, C++, C and Objective-C.

Is Nebulae Middleware free? What is the pricing?

Please reach out to us for pricing.

Can I use Nebulae Middleware with any device?

Yes, but you need to install the Nebulae Middleware device SDK on the device.
