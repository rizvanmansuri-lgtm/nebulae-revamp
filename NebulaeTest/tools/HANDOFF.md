## Per-batch workflow (do exactly this)
1. **Read each PDF** — `pdftotext -layout f.pdf - | iconv -c -t ascii` is fine for reading, but **check symbols in UTF-8**
   (ASCII conversion drops `µ ± × ° ®`; e.g. "60 A" was 60 µA). Long datasheets (15–25 p): read intro, key features, spec/electrical tables,
   ordering info, regulatory; skip programming/soldering chapters.
2. **Images**: `python3 tools/extract_images.py "<pdf>" /tmp/img/<slug>` then look at `/tmp/img/<slug>/sheet.png`.
   Skip backgrounds, icons, logos (Silicon Labs etc.). Real product photos / dimension drawings / pinouts / block diagrams are the keepers.
   Resize to ≤1100 px wide; save photos on white as `.jpg`, transparent/diagram as `.png`, name `<slug>-<what>.ext` into `assets/images/products/`.
   Some brochures have only ONE usable image — that's fine (gallery hides the thumbnail row when there is 1 image).
3. **Copy public PDFs** to `assets/docs/` with clean names (skip Confidential/Internal ones — see MANIFEST).
4. **Write `tools/batches/batchN.py`** (uses `mkjson.py`; run `python3 tools/batches/batchN.py`) which emits `tools/products/<slug>.json` (schema below). Data comes ONLY from the PDFs.
5. `python3 tools/build_pages.py` (validates fields/images/docs/icons, then builds everything).
6. `python3 tools/test_pages.py [--shots]` — all must PASS. Look at `tools/shots/*.png` (desktop tabs + mobile top) for visual issues.
7. Update the State section above + MANIFEST status. Summarise brochure conflicts for the owner.

## Content rules (decided with the owner)
- **Spec-table wins.** If a brochure contradicts itself (e.g. feature list vs. spec table), use the spec table and log the conflict for the owner.
- **Never invent** ratings, reviews, stock status, prices, lead times, MOQ, box contents. Ordering tab = part numbers from the PDF + "on request".
- Applications/feature descriptions may be short neutral paraphrases, never new numbers or claims.
- Keep the shared header/footer untouched (templates). Root-level file names, lower-case slug.
- Don't publish PDFs marked Confidential/Internal (MANIFEST lists them).
- Naming inconsistencies exist in the brochures (Node vs Module, NLN vs NM prefix); classification is recorded in MANIFEST (`type_key`). Flag, don't guess silently.

## Lessons learned (save time)
- `extract_images.py` output: skip 1100×3200-style tall gradients (brochure backgrounds), tiny logos, and blurry black/white/grey blobs (soft-mask shadows). Real product shots are usually the 400–900 px images.
- Brochure images with dotted/frame borders: crop 6 px from each edge, upscale 2× with LANCZOS (see EVK board photo in batch2 workflow).
- If a hero photo has a large empty margin (e.g. NLN0725-IS), crop to the object bbox with padding, upscale 2×.
- When a brochure drawing lists loose numbers (e.g. 120/80/55/199 mm), render the page region (`pdftoppm -r 110 -x -y -W -H`) and look before labelling axes.
- Related links: builder skips slugs that don't exist yet, so list intended relations even if not built.
- A datasheet marked Confidential/Internal can inform spec rows but must not be copied to `assets/docs/`; set `primary_doc` to the brochure or "".
- All pages share `body[data-pd-page]`; don't add page-specific CSS — add generic `pd-x-*` rules to the appended block in product-detail.css.
